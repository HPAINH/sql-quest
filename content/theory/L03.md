До этого уровня каждый запрос возвращал строки таблицы — может быть, отфильтрованные и пересчитанные, но по одной на объект. Отчёты устроены иначе: «сколько заказов в каждом статусе», «выручка по месяцам», «средний чек по городам». Тысячи строк нужно свернуть в несколько итоговых. Это делают **агрегатные функции** и **GROUP BY** — главный инструмент аналитика.

## Агрегатные функции

Агрегатная функция принимает много значений и возвращает одно.

| Функция | Что считает |
| --- | --- |
| `COUNT(*)` | число строк |
| `COUNT(x)` | число строк, где x не NULL |
| `COUNT(DISTINCT x)` | число разных не-NULL значений x |
| `SUM(x)` | сумму |
| `AVG(x)` | среднее арифметическое |
| `MIN(x)`, `MAX(x)` | минимум и максимум — для чисел, текста и дат |

Без `GROUP BY` агрегат сворачивает **всю** таблицу (после `WHERE`) в одну строку:

```sql
SELECT COUNT(*) AS orders_cnt,
       SUM(amount) AS revenue,
       ROUND(AVG(amount), 2) AS avg_check,
       MIN(created_at) AS first_order,
       MAX(created_at) AS last_order
FROM orders
WHERE status = 'delivered';
```

### Три вида COUNT

```sql
SELECT COUNT(*) AS all_rows,
       COUNT(phone) AS with_phone,
       COUNT(DISTINCT city) AS cities,
       COUNT(DISTINCT lower(email)) AS unique_emails
FROM customers;
```

- `COUNT(*)` — все строки, неважно, что в них;
- `COUNT(phone)` — только строки, где телефон заполнен;
- `COUNT(DISTINCT city)` — сколько разных городов.

Разница между числом клиентов и числом уникальных почт — это дубли аккаунтов: один человек зарегистрировался дважды, иногда с почтой в другом регистре.

> **Ловушка.** `COUNT(x)` и `COUNT(*)` отличаются только NULL-ами. Когда «что-то не сходится на пару процентов», первым делом проверь, не считает ли один из запросов колонку с пропусками.

## Агрегаты и NULL

Все агрегатные функции, кроме `COUNT(*)`, **пропускают NULL**.

- `AVG` делит сумму на число **не-NULL** значений. Среднее из 1, NULL и 3 — это 2, а не 4/3.
- `SUM` по пустому набору строк возвращает **NULL**, а не 0.
- `COUNT` по пустому набору возвращает 0.

```sql
SELECT COUNT(*) AS cnt,
       SUM(amount) AS sum_amount,
       COALESCE(SUM(amount), 0) AS sum_or_zero
FROM orders
WHERE status = 'lost_in_space';
```

Если NULL должен считаться нулём (например, «нет оценки = 0 баллов»), это нужно сделать явно: `AVG(COALESCE(rating, 0))`. Но чаще правильно именно пропускать: средняя оценка считается по тем, кто её поставил.

## GROUP BY: итоги по группам

`GROUP BY` разбивает строки на группы с одинаковыми значениями указанных колонок, и агрегаты считаются **для каждой группы отдельно**.

```sql
SELECT status,
       COUNT(*) AS orders_cnt,
       SUM(amount) AS revenue
FROM orders
GROUP BY status
ORDER BY orders_cnt DESC;
```

Как это работает:

1. `FROM` берёт все заказы.
2. `GROUP BY status` раскладывает их по «корзинам» — по одной на каждый статус.
3. Для каждой корзины вычисляются `COUNT(*)` и `SUM(amount)`.
4. Каждая корзина становится одной строкой результата.

### Главное правило

Каждая колонка в `SELECT` должна быть либо в `GROUP BY`, либо внутри агрегатной функции.

```sql-error
SELECT status, order_id, COUNT(*)
FROM orders
GROUP BY status;
```

В группе «delivered» тысячи заказов — какой `order_id` показать? База не угадывает и сообщает об ошибке: `column "orders.order_id" must appear in the GROUP BY clause or be used in an aggregate function`.

> **Важно.** PostgreSQL делает одно исключение: если в `GROUP BY` стоит первичный ключ таблицы, остальные её колонки можно выводить без агрегата — они однозначно определяются ключом. `GROUP BY c.customer_id` позволяет писать `c.first_name, c.city`. В других СУБД так нельзя, поэтому многие по привычке перечисляют все колонки.

### Несколько колонок

Группировка по нескольким колонкам создаёт группу на каждую **комбинацию**:

```sql
SELECT department,
       position,
       COUNT(*) AS people,
       ROUND(AVG(salary)) AS avg_salary
FROM employees
GROUP BY department, position
ORDER BY department, avg_salary DESC;
```

### Группировка по выражению

Группировать можно по вычисленному значению — например, по месяцу:

```sql
SELECT date_trunc('month', created_at)::date AS month,
       COUNT(*) AS orders_cnt,
       SUM(amount) AS revenue
FROM orders
WHERE created_at >= '2026-01-01'
GROUP BY date_trunc('month', created_at)::date
ORDER BY month;
```

PostgreSQL разрешает писать в `GROUP BY` псевдоним из `SELECT` (`GROUP BY month`) или номер колонки (`GROUP BY 1`). Это удобно в черновике, но в рабочих запросах выражение надёжнее: псевдоним может совпасть с именем настоящей колонки, и тогда группировка пойдёт по ней.

### Сортировка по агрегату

```sql
SELECT customer_id,
       COUNT(*) AS orders_cnt,
       SUM(amount) AS total
FROM orders
GROUP BY customer_id
ORDER BY total DESC
LIMIT 5;
```

Это классический «топ клиентов». `ORDER BY` выполняется после агрегации, поэтому ему доступны и агрегаты, и их псевдонимы.

## WHERE и HAVING

У группового запроса два места для условий, и они работают на разных этапах:

| | WHERE | HAVING |
| --- | --- | --- |
| Когда работает | до группировки | после группировки |
| Что фильтрует | строки | группы |
| Может использовать агрегаты | нет | да |

```sql
SELECT brand,
       COUNT(*) AS products_cnt,
       ROUND(AVG(price)) AS avg_price
FROM products
WHERE is_active
GROUP BY brand
HAVING COUNT(*) >= 20
ORDER BY products_cnt DESC;
```

Читается так: взять активные товары (`WHERE`), сгруппировать по бренду, оставить бренды, где таких товаров не меньше 20 (`HAVING`).

Условие на агрегат в `WHERE` написать нельзя — на этапе `WHERE` групп ещё нет:

```sql-error
SELECT brand, COUNT(*)
FROM products
WHERE COUNT(*) >= 20
GROUP BY brand;
```

> **Совет.** Условие, которое можно проверить по отдельной строке (`is_active`, `status = 'delivered'`, дата), ставь в `WHERE`, даже если технически его можно перенести в `HAVING`. Так база выбросит лишние строки до группировки и сделает меньше работы.

### Псевдоним в HAVING

PostgreSQL не разрешает ссылаться в `HAVING` на псевдоним из `SELECT`: `HAVING products_cnt >= 20` вызовет ошибку. Агрегат нужно повторить — `HAVING COUNT(*) >= 20`.

## Условная агрегация

Часто в одной строке нужны несколько счётчиков по разным условиям: всего заказов, из них отменено, из них возвращено. Можно было бы написать три запроса, но удобнее посчитать всё за один проход.

### FILTER

```sql
SELECT delivery_city,
       COUNT(*) AS orders_cnt,
       COUNT(*) FILTER (WHERE status = 'cancelled') AS cancelled,
       COUNT(*) FILTER (WHERE status = 'returned') AS returned,
       SUM(amount) FILTER (WHERE status = 'delivered') AS delivered_revenue
FROM orders
GROUP BY delivery_city
ORDER BY orders_cnt DESC
LIMIT 6;
```

`FILTER (WHERE …)` пропускает в агрегат только подходящие строки группы. Работает с любым агрегатом.

### SUM(CASE …)

`FILTER` есть в PostgreSQL, но не во всех СУБД. Универсальный способ — `CASE` внутри агрегата:

```sql
SELECT delivery_city,
       SUM(CASE WHEN status = 'cancelled' THEN 1 ELSE 0 END) AS cancelled,
       COUNT(CASE WHEN status = 'returned' THEN 1 END) AS returned
FROM orders
GROUP BY delivery_city
ORDER BY delivery_city
LIMIT 5;
```

`COUNT(CASE WHEN … THEN 1 END)` тоже работает: без `ELSE` неподходящие строки получают NULL, а `COUNT` его не считает.

### Доли и проценты

Доля = подходящие / все. Не забывай про целочисленное деление:

```sql
SELECT delivery_city,
       COUNT(*) AS orders_cnt,
       ROUND(100.0 * COUNT(*) FILTER (WHERE status = 'cancelled') / COUNT(*), 1) AS cancel_pct
FROM orders
GROUP BY delivery_city
ORDER BY cancel_pct DESC
LIMIT 5;
```

Удобный трюк: среднее от логического флага — это доля. `AVG((status = 'cancelled')::int)` даёт долю отменённых заказов от 0 до 1.

## Другие полезные агрегаты

| Функция | Что делает |
| --- | --- |
| `string_agg(x, ', ' ORDER BY x)` | склеивает значения группы в строку |
| `array_agg(x ORDER BY x)` | собирает значения группы в массив |
| `bool_and(cond)` | истина, если условие верно для всех строк группы |
| `bool_or(cond)` | истина, если условие верно хотя бы для одной |
| `percentile_cont(0.5) WITHIN GROUP (ORDER BY x)` | медиана (уровень 9) |

```sql
SELECT department,
       COUNT(*) AS people,
       string_agg(full_name, ', ' ORDER BY full_name) AS team
FROM employees
WHERE department IN ('Аналитика', 'Маркетинг')
GROUP BY department;
```

```sql
SELECT brand,
       bool_and(is_active) AS all_active,
       bool_or(NOT is_active) AS has_inactive
FROM products
GROUP BY brand
ORDER BY brand
LIMIT 6;
```

`MIN` и `MAX` работают не только с числами: `MIN(created_at)` — первая дата, `MAX(name)` — последнее по алфавиту название.

## DISTINCT внутри агрегатов

`COUNT(DISTINCT customer_id)` — сколько **разных** клиентов сделали заказы:

```sql
SELECT date_trunc('month', created_at)::date AS month,
       COUNT(*) AS orders_cnt,
       COUNT(DISTINCT customer_id) AS buyers
FROM orders
WHERE created_at >= '2026-03-01'
GROUP BY 1
ORDER BY 1;
```

Заказов больше, чем покупателей: многие покупают несколько раз в месяц. Перепутать эти числа — классическая ошибка отчёта «сколько у нас покупателей».

`SUM(DISTINCT x)` тоже существует, но почти всегда это ошибка: две разные покупки на одинаковую сумму посчитаются один раз.

## Порядок выполнения запроса

Теперь полная картина для запросов этого уровня:

1. `FROM` — источник строк.
2. `WHERE` — фильтр строк.
3. `GROUP BY` — раскладка по группам.
4. Вычисление агрегатов для каждой группы.
5. `HAVING` — фильтр групп.
6. `SELECT` — колонки и псевдонимы.
7. `DISTINCT`.
8. `ORDER BY` — сортировка.
9. `LIMIT` / `OFFSET`.

Из этого порядка следуют все правила уровня: агрегаты недоступны в `WHERE` (их ещё нет), доступны в `HAVING` и `ORDER BY`, а псевдонимы из `SELECT` видит только `ORDER BY`.

## Типичные ошибки

### Колонка не в GROUP BY

`SELECT city, first_name, COUNT(*) … GROUP BY city` — у города много имён, какое показать? Либо добавь колонку в `GROUP BY`, либо оберни в агрегат (`MIN(first_name)`, `string_agg(first_name, ', ')`), либо пересмотри задачу.

### Агрегат в WHERE

`WHERE SUM(amount) > 100000` — ошибка. Условия на агрегаты — только в `HAVING`.

### COUNT(*) вместо COUNT(DISTINCT …)

«Сколько клиентов купили в июне» — это `COUNT(DISTINCT customer_id)`, а не `COUNT(*)`, который посчитает заказы.

### Средняя доля вместо общей

Средняя из долей по городам не равна доле по всем заказам: маленький город с одним отменённым заказом даст 100% и сильно сдвинет среднее. Общую долю считай как сумму числителей, делённую на сумму знаменателей.

### SUM по пустой группе

Если ни одна строка не подошла, `SUM` вернёт NULL. В отчётах, где NULL выглядит как «нет данных», это может ввести в заблуждение — оборачивай в `COALESCE(SUM(x), 0)`.

### Целочисленная доля

`COUNT(*) FILTER (…) / COUNT(*)` — деление целых, результат 0. Нужно `100.0 * … / COUNT(*)`.

## Шпаргалка

| Задача | Как написать |
| --- | --- |
| Сколько строк | `COUNT(*)` |
| Сколько заполненных значений | `COUNT(col)` |
| Сколько разных значений | `COUNT(DISTINCT col)` |
| Итог по группам | `SELECT g, AGG(x) FROM t GROUP BY g` |
| Итог по месяцам | `GROUP BY date_trunc('month', ts)` |
| Фильтр строк | `WHERE …` до `GROUP BY` |
| Фильтр групп | `HAVING COUNT(*) > 10` |
| Счётчик по условию | `COUNT(*) FILTER (WHERE cond)` |
| То же без FILTER | `SUM(CASE WHEN cond THEN 1 ELSE 0 END)` |
| Доля в процентах | `ROUND(100.0 * COUNT(*) FILTER (WHERE cond) / COUNT(*), 1)` |
| Ноль вместо NULL | `COALESCE(SUM(x), 0)` |
| Значения группы в строку | `string_agg(x, ', ' ORDER BY x)` |
| Топ групп | `GROUP BY … ORDER BY SUM(x) DESC LIMIT n` |

## Проверь себя

?? Сколько строк вернёт `SELECT COUNT(*) FROM orders WHERE status = 'unknown'`?
:: Одну строку со значением 0. Агрегат без GROUP BY всегда возвращает ровно одну строку, даже если ни одна строка не подошла.

?? А сколько строк вернёт тот же запрос с `GROUP BY status`?
:: Ни одной. С GROUP BY строки результата — это группы, а групп нет.

?? Чему равно `AVG(x)` для значений 10, NULL, 20?
:: 15. NULL не участвует ни в сумме, ни в количестве.

?? Чем `COUNT(*) FILTER (WHERE rating = 5)` отличается от `WHERE rating = 5` с последующим `COUNT(*)`?
:: С WHERE в запросе остаются только пятёрки, и другие счётчики (например, общее число отзывов) посчитать уже нельзя. FILTER считает пятёрки, не выбрасывая остальные строки, — в той же строке можно вывести и общее число.

?? Почему `HAVING brand = 'Nova'` работает, но лучше писать `WHERE brand = 'Nova'`?
:: Условие не использует агрегаты, его можно проверить по каждой строке. В WHERE лишние строки отсеются до группировки, и база сделает меньше работы. Результат будет тем же.

?? Как одной строкой посчитать долю активных товаров?
:: `SELECT AVG(is_active::int) FROM products` — среднее от флага 0/1 равно доле единиц. Или `100.0 * COUNT(*) FILTER (WHERE is_active) / COUNT(*)` в процентах.
