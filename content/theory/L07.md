`GROUP BY` отвечает на вопрос «сколько в группе», но платит за это деталями: строки схлопываются, и отдельных заказов больше не видно. А аналитику часто нужно и то и другое сразу: заказ **и** средний чек его клиента рядом; товар **и** его место в категории; сотрудник **и** доля его зарплаты в фонде отдела. Для этого есть **оконные функции** — пожалуй, самый мощный инструмент аналитического SQL и любимая тема собеседований. На этом уровне разберём, как устроено окно, нумерацию и рейтинги, агрегаты по окну и задачу «топ-N в каждой группе».

## Окно вместо группы

Сравни два запроса. Первый считает среднюю цену по категориям — 25 строк на выходе:

```sql
SELECT category_id, ROUND(AVG(price)) AS avg_price
FROM products
GROUP BY category_id
ORDER BY category_id
LIMIT 5;
```

Второй делает то же вычисление, но **не схлопывает строки**: каждый товар остаётся, а средняя по его категории приписывается рядом.

```sql
SELECT product_id,
       name,
       category_id,
       price,
       ROUND(AVG(price) OVER (PARTITION BY category_id)) AS avg_in_category
FROM products
ORDER BY category_id, price DESC
LIMIT 8;
```

`OVER (…)` превращает обычную агрегатную функцию в **оконную**. Для каждой строки база определяет её **окно** — набор связанных строк — и считает функцию по этому окну. Результат записывается в текущую строку, а сама строка никуда не девается.

Теперь можно сравнивать товар с категорией прямо в одной строке:

```sql
SELECT name,
       category_id,
       price,
       ROUND(price - AVG(price) OVER (PARTITION BY category_id)) AS diff_from_cat_avg
FROM products
ORDER BY diff_from_cat_avg DESC
LIMIT 5;
```

## Анатомия OVER

```sql-static
функция(…) OVER (
  PARTITION BY …   -- на какие группы делить строки
  ORDER BY …       -- в каком порядке строки внутри группы
  ROWS / RANGE …   -- рамка: какие строки вокруг текущей (уровень 8)
)
```

Все три части необязательны.

| Запись | Окно для каждой строки |
| --- | --- |
| `OVER ()` | вся выборка (после `WHERE` и `GROUP BY`) |
| `OVER (PARTITION BY category_id)` | все строки той же категории |
| `OVER (ORDER BY created_at)` | строки от начала до текущей — нарастающий итог |
| `OVER (PARTITION BY customer_id ORDER BY created_at)` | заказы того же клиента от первого до текущего |

`PARTITION BY` похож на `GROUP BY`: делит строки на группы по значению колонок. Но группы не схлопываются — они просто задают границы окна.

### OVER () — вся выборка

Пустое окно удобно для долей от общего итога:

```sql
SELECT method,
       COUNT(*) AS payments_cnt,
       ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS share_pct
FROM payments
GROUP BY method
ORDER BY payments_cnt DESC;
```

Обрати внимание на `SUM(COUNT(*)) OVER ()`: сначала `GROUP BY` считает `COUNT(*)` по способам оплаты, а затем оконная функция суммирует эти счётчики по всем строкам результата. Оконные функции вычисляются **после** группировки, поэтому могут работать с агрегатами.

## Где вычисляются окна

Полный порядок выполнения запроса:

1. `FROM` и `JOIN`
2. `WHERE`
3. `GROUP BY` и агрегаты
4. `HAVING`
5. **оконные функции**
6. `SELECT` (псевдонимы)
7. `DISTINCT`
8. `ORDER BY`
9. `LIMIT` / `OFFSET`

Отсюда два важных следствия:

- окно видит только строки, прошедшие `WHERE`. Если отфильтровать заказы июня, `AVG(amount) OVER ()` будет средним по июню, а не по всей истории;
- оконную функцию **нельзя** использовать в `WHERE`, `GROUP BY` и `HAVING` — в этот момент её ещё нет.

```sql-error
SELECT name, price,
       RANK() OVER (ORDER BY price DESC) AS rnk
FROM products
WHERE RANK() OVER (ORDER BY price DESC) <= 3;
```

Решение — посчитать окно во внутреннем запросе или CTE и отфильтровать снаружи. Об этом раздел «Топ-N в каждой группе».

## Нумерация и рейтинги

Эти функции существуют только как оконные и требуют `ORDER BY` в окне.

| Функция | Что даёт для значений 100, 90, 90, 80 |
| --- | --- |
| `ROW_NUMBER()` | 1, 2, 3, 4 — уникальный номер, равные получают разные номера |
| `RANK()` | 1, 2, 2, 4 — равные делят место, следующее место пропускается |
| `DENSE_RANK()` | 1, 2, 2, 3 — равные делят место, без пропусков |

Посмотри на живых данных — в поддержке есть сотрудники с одинаковой зарплатой:

```sql
SELECT full_name,
       salary,
       ROW_NUMBER() OVER (ORDER BY salary DESC) AS row_num,
       RANK()       OVER (ORDER BY salary DESC) AS rnk,
       DENSE_RANK() OVER (ORDER BY salary DESC) AS dense_rnk
FROM employees
WHERE department = 'Поддержка'
ORDER BY salary DESC;
```

Какую выбрать:

- **ROW_NUMBER** — когда нужна ровно одна строка на позицию: «последний заказ клиента», «удалить дубли, оставив одну запись»;
- **RANK** — спортивный рейтинг: «двое делят второе место, третьего нет»;
- **DENSE_RANK** — «уровни»: «третья по величине зарплата» (даже если первых двух несколько).

> **Ловушка.** `ROW_NUMBER` при равных значениях раздаёт номера в **произвольном** порядке. Если важна воспроизводимость, добавь в `ORDER BY` окна тай-брейкер: `ROW_NUMBER() OVER (ORDER BY salary DESC, employee_id)`.

### Нумерация внутри групп

С `PARTITION BY` нумерация начинается заново в каждой группе:

```sql
SELECT customer_id,
       order_id,
       created_at,
       ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY created_at) AS order_num
FROM orders
WHERE customer_id IN (1, 2, 3)
ORDER BY customer_id, order_num;
```

`order_num = 1` — первый заказ клиента, 2 — второй, и так далее. Такая нумерация — основа анализа повторных покупок.

## Агрегаты как оконные функции

Любая агрегатная функция — `SUM`, `AVG`, `COUNT`, `MIN`, `MAX` — работает как оконная.

```sql
SELECT order_id,
       customer_id,
       amount,
       SUM(amount) OVER (PARTITION BY customer_id) AS customer_total,
       COUNT(*)    OVER (PARTITION BY customer_id) AS customer_orders,
       ROUND(100.0 * amount / SUM(amount) OVER (PARTITION BY customer_id), 1) AS pct_of_customer
FROM orders
WHERE customer_id = 44
ORDER BY created_at;
```

В каждой строке — заказ, сумма всех заказов клиента, их число и доля текущего заказа.

### Доля внутри группы

Доля заказа в выручке своего дня:

```sql
SELECT created_at::date AS day,
       order_id,
       amount,
       ROUND(100.0 * amount / SUM(amount) OVER (PARTITION BY created_at::date), 2) AS pct_of_day
FROM orders
WHERE created_at >= '2026-06-30'
ORDER BY pct_of_day DESC
LIMIT 5;
```

### Отклонение от группы

Насколько зарплата отличается от средней по отделу:

```sql
SELECT department,
       full_name,
       salary,
       ROUND(AVG(salary) OVER (PARTITION BY department)) AS dept_avg,
       ROUND(salary - AVG(salary) OVER (PARTITION BY department)) AS diff
FROM employees
WHERE department = 'Аналитика'
ORDER BY diff DESC;
```

> **Важно.** Если в окне есть `ORDER BY`, агрегат становится **нарастающим**: `SUM(amount) OVER (PARTITION BY customer_id ORDER BY created_at)` — сумма от первого заказа до текущего, а не по всем заказам. Для итога по всей группе `ORDER BY` в окне не пиши. Подробно про это поведение («рамку окна») — на уровне 8.

## Топ-N в каждой группе

Классическая задача: три самых дорогих товара в каждой категории, последний заказ каждого клиента, лучший сотрудник каждого отдела. Схема всегда одна:

1. Во внутреннем запросе или CTE пронумеровать строки внутри групп.
2. Снаружи оставить строки с нужными номерами.

```sql
WITH ranked AS (
  SELECT category_id,
         name,
         price,
         ROW_NUMBER() OVER (PARTITION BY category_id ORDER BY price DESC, product_id) AS rn
  FROM products
  WHERE is_active
)
SELECT category_id, rn, name, price
FROM ranked
WHERE rn <= 3
ORDER BY category_id, rn
LIMIT 12;
```

Последний заказ каждого клиента:

```sql
WITH ranked AS (
  SELECT customer_id,
         order_id,
         created_at,
         amount,
         ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY created_at DESC) AS rn
  FROM orders
)
SELECT customer_id, order_id, created_at, amount
FROM ranked
WHERE rn = 1
ORDER BY customer_id
LIMIT 5;
```

### ROW_NUMBER или RANK в топ-N

Если на границе ничья, `ROW_NUMBER` отрежет ровно N строк (выбрав произвольно среди равных), а `RANK` — вернёт всех, кто делит N-е место, и строк может стать больше N. Выбор зависит от задачи: «покажи три товара» — ROW_NUMBER; «все, кто в тройке лучших по цене» — RANK или DENSE_RANK.

### DISTINCT ON — короткий путь для «одной строки на группу»

В PostgreSQL есть собственная конструкция для N = 1:

```sql
SELECT DISTINCT ON (customer_id)
       customer_id, order_id, created_at, amount
FROM orders
ORDER BY customer_id, created_at DESC
LIMIT 5;
```

`DISTINCT ON (customer_id)` оставляет первую строку каждой группы в порядке `ORDER BY`. Правило: колонки `DISTINCT ON` должны стоять первыми в `ORDER BY`. Это компактно, но работает только в PostgreSQL и только для одной строки на группу — на собеседованиях ждут вариант с `ROW_NUMBER`.

## Поиск дублей

Оконные функции удобны для дублей: пронумеровать записи внутри группы «одинаковых» и оставить первую.

```sql
WITH numbered AS (
  SELECT customer_id,
         email,
         registered_at,
         ROW_NUMBER() OVER (PARTITION BY lower(email) ORDER BY registered_at) AS rn,
         COUNT(*)     OVER (PARTITION BY lower(email)) AS copies
  FROM customers
)
SELECT customer_id, email, registered_at, rn
FROM numbered
WHERE copies > 1
ORDER BY lower(email), rn
LIMIT 8;
```

`rn = 1` — оригинальный аккаунт (самый ранний), `rn > 1` — дубли. На уровне 10 этот же приём поможет удалить дубли из таблицы.

## Именованное окно

Если одно и то же окно нужно нескольким функциям, его можно объявить один раз в предложении `WINDOW`:

```sql
SELECT full_name,
       department,
       salary,
       RANK() OVER w AS rnk,
       ROUND(AVG(salary) OVER w_dept) AS dept_avg
FROM employees
WINDOW w_dept AS (PARTITION BY department),
       w      AS (PARTITION BY department ORDER BY salary DESC)
ORDER BY department, rnk
LIMIT 8;
```

`WINDOW` пишется после `WHERE`/`GROUP BY`/`HAVING` и перед `ORDER BY`.

## Типичные ошибки

### Оконная функция в WHERE

`window functions are not allowed in WHERE` — посчитай окно в CTE и фильтруй снаружи.

### ORDER BY в окне, где нужен итог

`SUM(x) OVER (PARTITION BY g ORDER BY ts)` — нарастающий итог, а не сумма группы. Для доли от группы убери `ORDER BY` из окна.

### Нумерация без PARTITION BY

`ROW_NUMBER() OVER (ORDER BY created_at)` нумерует заказы сквозь всех клиентов. «Номер заказа клиента» требует `PARTITION BY customer_id`.

### Ничьи в ROW_NUMBER

Результат меняется от запуска к запуску, если в `ORDER BY` окна есть ничьи. Добавь ключ в конец сортировки.

### Сортировка окна и сортировка результата — разные вещи

`ORDER BY` внутри `OVER` задаёт порядок для вычисления функции, но не сортирует результат. Для упорядоченной выдачи нужен обычный `ORDER BY` в конце запроса.

### Ожидание, что окно видит отфильтрованные строки

Окно считается по строкам после `WHERE`. Если нужна средняя по всей истории, а показать только июнь, — посчитай окно в CTE без фильтра, а фильтр по дате примени снаружи.

## Шпаргалка

| Задача | Как написать |
| --- | --- |
| Значение группы в каждой строке | `AVG(x) OVER (PARTITION BY g)` |
| Доля от общего итога | `x / SUM(x) OVER ()` |
| Доля внутри группы | `x / SUM(x) OVER (PARTITION BY g)` |
| Доля после GROUP BY | `COUNT(*) / SUM(COUNT(*)) OVER ()` |
| Порядковый номер в группе | `ROW_NUMBER() OVER (PARTITION BY g ORDER BY ts)` |
| Рейтинг с пропусками | `RANK() OVER (ORDER BY x DESC)` |
| Рейтинг без пропусков | `DENSE_RANK() OVER (ORDER BY x DESC)` |
| Топ-N в группе | CTE с `ROW_NUMBER() … AS rn`, снаружи `WHERE rn <= N` |
| Одна строка на группу (PostgreSQL) | `SELECT DISTINCT ON (g) … ORDER BY g, ts DESC` |
| Дубли | `ROW_NUMBER() OVER (PARTITION BY key ORDER BY ts)`, дубли — `rn > 1` |
| Одно окно для нескольких функций | `… OVER w … WINDOW w AS (…)` |

## Проверь себя

?? Чем `AVG(price) OVER (PARTITION BY category_id)` отличается от `AVG(price) … GROUP BY category_id`?
:: Окно не схлопывает строки: каждый товар остаётся в результате со средней своей категории рядом. GROUP BY вернёт одну строку на категорию.

?? Для зарплат 300, 200, 200, 100 какие значения дадут ROW_NUMBER, RANK и DENSE_RANK при сортировке по убыванию?
:: ROW_NUMBER: 1, 2, 3, 4. RANK: 1, 2, 2, 4. DENSE_RANK: 1, 2, 2, 3.

?? Почему нельзя написать `WHERE ROW_NUMBER() OVER (…) = 1`?
:: Оконные функции вычисляются после WHERE. Нужно посчитать номер в подзапросе или CTE и отфильтровать во внешнем запросе.

?? Как найти третью по величине зарплату в компании, если у нескольких людей одинаковые зарплаты?
:: `DENSE_RANK() OVER (ORDER BY salary DESC)` в CTE и снаружи `WHERE rnk = 3`. DENSE_RANK не пропускает места, поэтому «третья» — это третье по величине значение.

?? Что вернёт `SUM(amount) OVER (PARTITION BY customer_id ORDER BY created_at)`?
:: Нарастающую сумму заказов клиента — от первого до текущего, а не общую сумму клиента.

?? Чем `SUM(COUNT(*)) OVER ()` отличается от `COUNT(*) OVER ()` в запросе с GROUP BY?
:: `SUM(COUNT(*)) OVER ()` складывает счётчики групп — получается общее число исходных строк. `COUNT(*) OVER ()` считает строки результата — то есть число групп.
