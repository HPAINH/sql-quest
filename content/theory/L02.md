До сих пор мы брали колонки «как есть». Но отчёту часто нужны новые значения: полное имя из имени и фамилии, домен почты, месяц заказа, маржа товара, ценовой сегмент, срок доставки в днях. Всё это вычисляется прямо в `SELECT` — выражениями и функциями. На этом уровне разберём работу с числами, текстом, датами, условную логику `CASE` и функции для NULL.

## Выражения в SELECT

В `SELECT` можно писать не только имена колонок, но и любые выражения. Результат выражения — новая колонка, которой стоит дать имя.

```sql
SELECT name,
       price,
       cost,
       price - cost AS margin,
       round((price - cost) / price * 100, 1) AS margin_pct
FROM products
ORDER BY margin_pct DESC
LIMIT 5;
```

Выражение вычисляется **для каждой строки отдельно** — в этом отличие от агрегатных функций (уровень 3), которые сворачивают много строк в одно значение.

Выражения можно использовать и в `WHERE`, и в `ORDER BY`. А вот псевдоним из `SELECT` в `WHERE` недоступен — там выражение придётся повторить.

## Числа

### Арифметика

| Операция | Пример | Результат |
| --- | --- | --- |
| Сложение, вычитание | `price - cost` | разница |
| Умножение | `quantity * price` | сумма позиции |
| Деление | `7 / 2.0` | 3.5 |
| Остаток от деления | `7 % 3` | 1 |
| Возведение в степень | `2 ^ 10` | 1024 |

### Ловушка целочисленного деления

Если **оба** числа целые, деление тоже целое — дробная часть отбрасывается:

```sql
SELECT 7 / 2 AS int_div,
       7 / 2.0 AS num_div,
       7::numeric / 2 AS cast_div;
```

Это одна из самых частых ошибок в аналитике: доля `cancelled_cnt / total_cnt` между двумя целыми счётчиками всегда равна 0 (если не 100%). Решение — привести хотя бы одно число к дробному типу:

- `x::numeric / y` — привести к numeric;
- `x * 1.0 / y` — умножить на дробную единицу;
- `x * 100.0 / y` — сразу проценты.

> **Ловушка.** `COUNT(*)` и колонки вроде `quantity` или `rating` — целые. Любое их деление друг на друга — повод проверить, не потерялась ли дробная часть.

### Деление на ноль

`x / 0` вызывает ошибку и роняет весь запрос:

```sql-error
SELECT 100 / 0 AS boom;
```

Защита — превратить ноль в NULL через `NULLIF`: `x / NULLIF(y, 0)`. Деление на NULL даёт NULL, а не ошибку. Подробнее о `NULLIF` — в конце уровня.

### Округление

| Функция | Что делает | `2.567` | `-2.5` |
| --- | --- | --- | --- |
| `round(x)` | до целого по правилам арифметики | 3 | -3 |
| `round(x, 2)` | до 2 знаков после запятой | 2.57 | -2.50 |
| `ceil(x)` | вверх, до ближайшего целого | 3 | -2 |
| `floor(x)` | вниз | 2 | -3 |
| `trunc(x, 1)` | отбросить лишние знаки | 2.5 | -2.5 |
| `abs(x)` | модуль | 2.567 | 2.5 |

```sql
SELECT name,
       price,
       round(price * 0.85) AS sale_price,
       ceil(price / 1000) * 1000 AS rounded_up_to_thousand
FROM products
WHERE brand = 'Volt'
ORDER BY price
LIMIT 5;
```

> **Важно.** `round(x, n)` с числом знаков работает для типа `numeric`. Для `double precision` (так возвращают результат, например, `percentile_cont` и `date_part`) PostgreSQL выдаст ошибку `function round(double precision, integer) does not exist`. Решение — приведение: `round(x::numeric, 2)`.

## Приведение типов

У каждого значения есть тип: `integer`, `numeric`, `text`, `date`, `timestamp`, `boolean`, `interval`, `jsonb`. Иногда тип нужно поменять. В PostgreSQL для этого есть короткая запись `::`:

```sql
SELECT '2026-06-15'::date AS d,
       '42'::int + 1 AS n,
       12.7::int AS rounded,
       price::text AS price_text
FROM products
LIMIT 1;
```

Стандартная форма — `CAST(x AS type)`, она делает то же самое.

Если значение нельзя привести, запрос падает:

```sql-error
SELECT '2026-02-30'::date;
```

> **Совет.** Приведение колонки «на лету» (`customer_id::text = '42'`) не только выглядит странно, но и мешает индексам. На уровне 11 увидишь, как такое условие превращает быстрый поиск в полный проход по таблице.

## Текст

### Склейка

Оператор `||` склеивает строки:

```sql
SELECT first_name || ' ' || last_name AS full_name, city
FROM customers
LIMIT 5;
```

Если хоть одна часть равна NULL, весь результат `||` станет NULL. Функции `concat` и `concat_ws` пропускают NULL:

```sql
SELECT 'Тел: ' || phone AS with_pipes,
       concat('Тел: ', phone) AS with_concat,
       concat_ws(', ', city, phone) AS city_phone
FROM customers
WHERE phone IS NULL
LIMIT 3;
```

`concat_ws(разделитель, a, b, …)` — склейка через разделитель, NULL просто пропускаются вместе с разделителем.

### Основные функции

| Функция | Пример | Результат |
| --- | --- | --- |
| `lower(s)`, `upper(s)` | `lower('Mail.RU')` | `mail.ru` |
| `initcap(s)` | `initcap('иван петров')` | `Иван Петров` |
| `length(s)` | `length('ShopData')` | 8 |
| `left(s, n)`, `right(s, n)` | `left('Москва', 3)` | `Мос` |
| `substring(s from i for n)` | `substring('ShopData' from 5 for 4)` | `Data` |
| `position(sub in s)` | `position('@' in 'a@b.ru')` | 2 |
| `split_part(s, sep, n)` | `split_part('anna@mail.ru', '@', 2)` | `mail.ru` |
| `replace(s, from, to)` | `replace('+7 900', ' ', '')` | `+7900` |
| `trim(s)` | `trim('  x  ')` | `x` |
| `lpad(s, n, fill)` | `lpad('42', 5, '0')` | `00042` |
| `regexp_replace(s, re, to, 'g')` | `regexp_replace('+7 (900) 1', '[^0-9]', '', 'g')` | `79001` |

```sql
SELECT email,
       split_part(email, '@', 1) AS login,
       lower(split_part(email, '@', 2)) AS domain
FROM customers
LIMIT 5;
```

> **Совет.** Почты, бренды и города из разных систем часто приходят в разном регистре и с пробелами. Перед сравнением или группировкой нормализуй: `lower(trim(email))`. В ShopData у части клиентов домен записан заглавными — проверь, сколько разных доменов получится без `lower` и с ним.

## Даты и время

### Типы

- `date` — только дата: `2026-06-15`.
- `timestamp` — дата и время без часового пояса: `2026-06-15 18:30:00`.
- `timestamptz` — момент времени с учётом пояса.
- `interval` — длительность: `3 days`, `1 day 02:30:00`, `2 mons`.

В ShopData `orders.created_at`, `payments.paid_at`, `events.event_ts` — timestamp; `products.created_at`, `customers.birth_date`, `employees.hired_at` — date.

### «Сегодня» в задачах

Данные заканчиваются 30 июня 2026 года, поэтому в тикетах «сегодня» — это **1 июля 2026**. Не используй `now()` или `current_date`: ответ будет зависеть от дня, когда запущен запрос, и проверка его не примет. Вместо этого пиши дату явно: `'2026-07-01'::date`.

### Отрезать время и округлить период

```sql
SELECT order_id,
       created_at,
       created_at::date AS order_date,
       date_trunc('month', created_at) AS order_month,
       date_trunc('week', created_at) AS order_week
FROM orders
ORDER BY created_at DESC
LIMIT 5;
```

`date_trunc(unit, ts)` «обрезает» время до начала периода: `'year'`, `'quarter'`, `'month'`, `'week'` (неделя начинается с понедельника), `'day'`, `'hour'`. Результат остаётся датой-временем, поэтому его удобно группировать и сортировать. Если нужна именно дата, добавь `::date`.

### Достать часть даты

```sql
SELECT order_id,
       created_at,
       EXTRACT(YEAR FROM created_at) AS y,
       EXTRACT(MONTH FROM created_at) AS m,
       EXTRACT(DOW FROM created_at) AS dow,
       EXTRACT(HOUR FROM created_at) AS h
FROM orders
LIMIT 5;
```

| Поле | Значение |
| --- | --- |
| `YEAR`, `MONTH`, `DAY` | год, месяц 1–12, день месяца |
| `QUARTER` | квартал 1–4 |
| `DOW` | день недели: 0 — воскресенье, 6 — суббота |
| `ISODOW` | день недели по ISO: 1 — понедельник, 7 — воскресенье |
| `HOUR`, `MINUTE` | час, минута |
| `EPOCH` | секунды с 1970 года (для интервала — длительность в секундах) |

> **Ловушка.** `EXTRACT(MONTH …) = 6` — это июнь **любого** года. Если в данных несколько лет, а нужен июнь 2026-го, добавь год или, лучше, используй диапазон дат. А `date_trunc('month', created_at)` сохраняет год и не путает июнь 2025 с июнем 2026.

### Арифметика дат

| Выражение | Результат |
| --- | --- |
| `date '2026-07-01' - date '2026-06-01'` | `30` — целое число дней |
| `timestamp_a - timestamp_b` | интервал, например `1 day 01:30:00` |
| `date '2026-06-30' + 1` | следующий день |
| `created_at + interval '7 days'` | на неделю позже |
| `created_at - interval '1 month'` | на месяц раньше |
| `age('2026-07-01', birth_date)` | интервал в годах, месяцах, днях |

```sql
SELECT order_id,
       shipped_at,
       delivered_at,
       delivered_at - shipped_at AS took,
       EXTRACT(EPOCH FROM delivered_at - shipped_at) / 86400 AS took_days
FROM deliveries
WHERE delivered_at IS NOT NULL
ORDER BY took DESC
LIMIT 5;
```

Возраст клиента на «сегодня»:

```sql
SELECT first_name,
       birth_date,
       EXTRACT(YEAR FROM age('2026-07-01', birth_date)) AS age_years
FROM customers
WHERE birth_date IS NOT NULL
ORDER BY birth_date DESC
LIMIT 5;
```

### Форматирование

`to_char` превращает дату или число в текст по шаблону: `to_char(created_at, 'DD.MM.YYYY HH24:MI')` даст `15.06.2026 18:30`. Для отчётов это удобно, но сортировать и сравнивать нужно исходные даты: текст `'01.07.2026'` меньше `'15.06.2026'`.

## CASE: условная логика

`CASE` выбирает значение в зависимости от условий. Это `if … else` внутри SQL.

```sql
SELECT name,
       price,
       CASE
         WHEN price < 1000 THEN 'до 1000'
         WHEN price < 10000 THEN '1000–9999'
         WHEN price < 50000 THEN '10 000–49 999'
         ELSE '50 000 и дороже'
       END AS price_band
FROM products
ORDER BY price
LIMIT 10;
```

Правила:

- ветки `WHEN` проверяются **сверху вниз**, срабатывает первая истинная — поэтому во второй ветке не нужно писать `price >= 1000`;
- если ни одна ветка не подошла и нет `ELSE`, результат — NULL;
- все ветки должны возвращать значения одного типа (нельзя смешать число и текст);
- `CASE` заканчивается словом `END`, после него — псевдоним.

### Короткая форма

Когда сравнивается одно выражение с разными значениями, есть короткая запись:

```sql
SELECT order_id,
       status,
       CASE status
         WHEN 'new' THEN 'Новый'
         WHEN 'paid' THEN 'Оплачен'
         WHEN 'shipped' THEN 'В пути'
         WHEN 'delivered' THEN 'Доставлен'
         ELSE 'Отменён или возвращён'
       END AS status_ru
FROM orders
ORDER BY order_id DESC
LIMIT 6;
```

### CASE и NULL

Короткая форма сравнивает через `=`, поэтому `CASE phone WHEN NULL THEN …` никогда не сработает. Для NULL используй полную форму: `CASE WHEN phone IS NULL THEN 'нет телефона' ELSE phone END`.

### CASE в ORDER BY

`CASE` можно использовать для своего порядка сортировки — например, статусы по ходу жизни заказа, а не по алфавиту:

```sql
SELECT order_id, status, created_at
FROM orders
WHERE created_at >= '2026-06-29'
ORDER BY CASE status
           WHEN 'new' THEN 1
           WHEN 'paid' THEN 2
           WHEN 'shipped' THEN 3
           WHEN 'delivered' THEN 4
           ELSE 5
         END,
         created_at;
```

Свежие заказы оказываются наверху, доставленные и отменённые — внизу. С `SELECT DISTINCT` такой трюк не пройдёт: при `DISTINCT` сортировать можно только по выражениям, которые есть в списке `SELECT`.

### CASE как флаг

`CASE` часто превращает условие в 0 или 1 — это основа условной агрегации на следующем уровне:

```sql
SELECT order_id,
       amount,
       CASE WHEN amount >= 100000 THEN 1 ELSE 0 END AS is_big
FROM orders
LIMIT 5;
```

## Функции для NULL

### COALESCE — первое не-NULL значение

`COALESCE(a, b, c, …)` возвращает первый аргумент, который не равен NULL.

```sql
SELECT first_name,
       last_name,
       COALESCE(phone, 'не указан') AS phone
FROM customers
ORDER BY customer_id
LIMIT 6;
```

Типичные применения:

- подставить значение по умолчанию: `COALESCE(discount_pct, 0)`;
- выбрать первое заполненное из нескольких источников: `COALESCE(mobile, work_phone, home_phone)`;
- превратить NULL в 0 после LEFT JOIN (уровень 4).

Типы всех аргументов должны совпадать: `COALESCE(birth_date, 'нет')` упадёт, потому что дата и текст несовместимы. Приведи дату к тексту: `COALESCE(birth_date::text, 'нет')`.

### NULLIF — превратить значение в NULL

`NULLIF(a, b)` возвращает NULL, если `a = b`, иначе — `a`. Главные применения:

- защита от деления на ноль: `x / NULLIF(y, 0)`;
- «пустая строка — это тоже отсутствие значения»: `NULLIF(trim(text), '')`.

```sql
SELECT 10 / NULLIF(0, 0) AS safe_div,
       NULLIF('', '') AS empty_to_null,
       COALESCE(NULLIF('', ''), 'пусто') AS combo;
```

### GREATEST и LEAST

`GREATEST(a, b, …)` и `LEAST(a, b, …)` — максимум и минимум **из нескольких значений одной строки** (не путать с агрегатными `MAX` и `MIN`, которые ищут по многим строкам). NULL-аргументы они пропускают.

```sql
SELECT name, price, GREATEST(price * 0.8, cost) AS floor_price
FROM products
LIMIT 5;
```

Здесь цена со скидкой 20% не опускается ниже себестоимости.

## Типичные ошибки

### Доля, которая всегда 0

`SELECT 3 / 4` — это 0. Если делишь целые, приведи одно из них: `3::numeric / 4` или `3 * 100.0 / 4`.

### now() в отчёте

Запрос с `now()` сегодня даёт один ответ, завтра — другой. В тикетах «сегодня» — 2026-07-01, пиши дату явно.

### Склейка с NULL

`first_name || ' ' || phone` даёт NULL у всех клиентов без телефона. Если строка должна остаться, используй `concat` или `COALESCE(phone, '')`.

### EXTRACT вместо периода

Условие `EXTRACT(MONTH FROM created_at) = 12` собирает декабри всех лет. Для конкретного декабря — диапазон `>= '2025-12-01' AND < '2026-01-01'`.

### CASE без ELSE

Если ветки не покрывают все значения, «непредусмотренные» получат NULL — и могут потеряться в отчёте. Добавляй `ELSE` даже на всякий случай, например `ELSE 'другое'`.

### Порядок веток CASE

```sql-static
CASE WHEN price < 10000 THEN 'средний'
     WHEN price < 1000  THEN 'бюджет'   -- никогда не сработает
END
```

Товар за 500 ₽ попадёт в первую ветку. Узкие условия ставь раньше широких.

## Шпаргалка

| Задача | Как написать |
| --- | --- |
| Доля с дробной частью | `a::numeric / b`, `a * 100.0 / b` |
| Безопасное деление | `a / NULLIF(b, 0)` |
| Округлить до 2 знаков | `round(x, 2)`, для double — `round(x::numeric, 2)` |
| Полное имя | `first_name \|\| ' ' \|\| last_name` |
| Склейка без потери NULL | `concat_ws(' ', a, b, c)` |
| Домен почты | `lower(split_part(email, '@', 2))` |
| Дата без времени | `created_at::date` |
| Начало месяца | `date_trunc('month', created_at)` |
| Год, месяц, день недели | `EXTRACT(YEAR FROM ts)`, `EXTRACT(ISODOW FROM ts)` |
| Дней между датами | `date2 - date1` |
| Длительность в часах | `EXTRACT(EPOCH FROM ts2 - ts1) / 3600` |
| Возраст | `EXTRACT(YEAR FROM age('2026-07-01', birth_date))` |
| Категория по условию | `CASE WHEN … THEN … ELSE … END` |
| Значение по умолчанию | `COALESCE(x, 0)` |

## Проверь себя

?? Сколько будет `SELECT 5 / 2 * 2`?
:: 4. Сначала `5 / 2` — это целое 2, затем `2 * 2 = 4`. С `5 / 2.0 * 2` получится 5.

?? Что вернёт `CASE WHEN price > 1000 THEN 'дорого' END` для товара за 500 ₽?
:: NULL — подходящей ветки нет, а `ELSE` не указан.

?? Чем `date_trunc('month', created_at)` лучше `EXTRACT(MONTH FROM created_at)` для отчёта по месяцам?
:: date_trunc сохраняет год: июнь 2025 и июнь 2026 будут разными значениями. EXTRACT вернёт 6 для обоих, и месяцы разных лет смешаются.

?? Как получить число полных дней между отгрузкой и вручением?
:: `delivered_at::date - shipped_at::date` даёт разницу календарных дат. Если нужны полные сутки по времени — `EXTRACT(DAY FROM delivered_at - shipped_at)` или `floor(EXTRACT(EPOCH FROM delivered_at - shipped_at) / 86400)`.

?? `COALESCE(NULL, 0, 5)` — что вернёт?
:: 0 — это первый аргумент, который не NULL. То, что он «ложный» или нулевой, значения не имеет.

?? Почему `concat('Тел: ', phone)` и `'Тел: ' || phone` дают разный результат для клиентов без телефона?
:: `||` с NULL даёт NULL, а `concat` воспринимает NULL как пустую строку и вернёт `Тел: `.
