Отчёт почти никогда не нужен по всей таблице. Нужны заказы за июнь, клиенты из Казани, товары дешевле тысячи, отзывы без текста. Отбор строк делает `WHERE` — и это самая частая часть любого запроса. На этом уровне ты разберёшься с условиями, логикой, шаблонами и главной ловушкой SQL — значением NULL.

## WHERE: оставить нужные строки

`WHERE` проверяет условие для каждой строки таблицы. Строка попадает в результат, только если условие **истинно**.

```sql
SELECT name, brand, price
FROM products
WHERE price < 1000
ORDER BY price;
```

`WHERE` всегда идёт сразу после `FROM`, до `ORDER BY` и `LIMIT`:

```sql-static
SELECT …
FROM …
WHERE …
ORDER BY …
LIMIT …
```

Условие может использовать любые колонки таблицы, даже те, которых нет в `SELECT`:

```sql
SELECT first_name, last_name
FROM customers
WHERE city = 'Казань'
ORDER BY last_name
LIMIT 10;
```

## Операторы сравнения

| Оператор | Смысл | Пример |
| --- | --- | --- |
| `=` | равно | `status = 'paid'` |
| `<>` или `!=` | не равно | `status <> 'cancelled'` |
| `<`, `>` | меньше, больше | `price > 50000` |
| `<=`, `>=` | меньше или равно, больше или равно | `rating <= 2` |

Сравнивать можно числа, текст, даты и время.

### Как писать значения

- **Числа** пишутся как есть: `price > 1500`, `discount_pct = 20`. Дробная часть — через точку: `9.99`.
- **Текст** — в одинарных кавычках: `city = 'Москва'`. Если в тексте есть апостроф, его удваивают: `'Д''Артаньян'`.
- **Даты и время** — тоже в одинарных кавычках, в формате ISO: `'2026-06-15'` или `'2026-06-15 18:30'`. PostgreSQL сам приведёт строку к типу колонки.
- **Логические** значения — `true` и `false`.

```sql
SELECT order_id, created_at, amount
FROM orders
WHERE created_at >= '2026-06-30 20:00'
ORDER BY created_at;
```

> **Ловушка.** Текст сравнивается с учётом регистра: `'москва'` не равно `'Москва'`. Если данные пришли из разных источников, регистр может «гулять» — тогда сравнивают через `lower(…)` или используют `ILIKE` (см. ниже).

### Логические колонки

Колонка типа `boolean` уже является условием — сравнивать её с `true` не нужно:

```sql
SELECT name, price
FROM products
WHERE NOT is_active
ORDER BY price DESC
LIMIT 5;
```

`WHERE is_active` — активные товары, `WHERE NOT is_active` — снятые с продажи.

## AND, OR, NOT

Условия комбинируются логическими операторами:

- `A AND B` — истинно, когда истинны оба;
- `A OR B` — истинно, когда истинно хотя бы одно;
- `NOT A` — переворачивает условие.

```sql
SELECT name, brand, price
FROM products
WHERE brand = 'Nova' AND price < 2000 AND is_active
ORDER BY price;
```

### Приоритет: AND раньше OR

`AND` связывает сильнее, чем `OR` — так же, как умножение сильнее сложения. Поэтому

```sql-static
WHERE status = 'cancelled' OR status = 'returned' AND amount > 50000
```

PostgreSQL прочитает как

```sql-static
WHERE status = 'cancelled' OR (status = 'returned' AND amount > 50000)
```

— все отменённые заказы плюс крупные возвраты. Если имелись в виду «крупные заказы, которые отменили или вернули», нужны скобки:

```sql
SELECT order_id, status, amount
FROM orders
WHERE (status = 'cancelled' OR status = 'returned') AND amount > 300000
ORDER BY amount DESC;
```

> **Совет.** Смешиваешь `AND` и `OR` — ставь скобки, даже если уверен в приоритете. Через месяц ты или коллега прочитаете запрос быстрее.

### NOT и законы де Моргана

`NOT (A OR B)` — то же, что `NOT A AND NOT B`. `NOT (A AND B)` — то же, что `NOT A OR NOT B`. Это пригодится, когда нужно «перевернуть» сложное условие: «не Москва и не Петербург» записывается как `city <> 'Москва' AND city <> 'Санкт-Петербург'`, а не через `OR` — с `OR` условие будет истинно для всех городов.

## IN и BETWEEN

### IN — значение из списка

Вместо цепочки `OR` удобнее перечислить значения:

```sql
SELECT order_id, status, created_at
FROM orders
WHERE status IN ('new', 'paid')
ORDER BY created_at DESC
LIMIT 10;
```

`NOT IN` — значение не входит в список:

```sql
SELECT full_name, department
FROM employees
WHERE department NOT IN ('Продажи', 'Поддержка', 'Логистика')
ORDER BY department, full_name;
```

### BETWEEN — диапазон

`x BETWEEN a AND b` — то же, что `x >= a AND x <= b`. **Обе границы включаются.**

```sql
SELECT name, price
FROM products
WHERE price BETWEEN 5000 AND 6000
ORDER BY price;
```

### Ловушка BETWEEN с датами и временем

Колонка `orders.created_at` хранит дату **и время**. Строка `'2026-06-30'` превращается в «30 июня, 00:00:00». Поэтому

```sql
SELECT COUNT(*) AS june_orders
FROM orders
WHERE created_at BETWEEN '2026-06-01' AND '2026-06-30';
```

не посчитает почти все заказы 30 июня — всё, что оформили после полуночи. Надёжный способ — **полуоткрытый интервал**: начало включаем, конец исключаем.

```sql
SELECT COUNT(*) AS june_orders
FROM orders
WHERE created_at >= '2026-06-01'
  AND created_at <  '2026-07-01';
```

Сравни два числа: разница — это заказы, потерянные первым запросом. Полуоткрытый интервал работает для любой точности времени и легко сдвигается: следующий месяц — `>= '2026-07-01' AND < '2026-08-01'`.

> **Совет.** Для периодов по колонкам с временем всегда пиши `>= начало AND < начало_следующего_периода`. Это правило избавит от целого класса ошибок в отчётах.

## LIKE и ILIKE: поиск по шаблону

`LIKE` сравнивает текст с шаблоном, где есть два специальных символа:

- `%` — любое количество любых символов, в том числе ноль;
- `_` — ровно один любой символ.

| Шаблон | Подходит |
| --- | --- |
| `'Смарт%'` | начинается со «Смарт» |
| `'%Pro'` | заканчивается на «Pro» |
| `'%Nova%'` | содержит «Nova» где угодно |
| `'_____'` | ровно пять символов |
| `'%@gmail.com'` | почта на gmail.com |

```sql
SELECT name, price
FROM products
WHERE name LIKE 'Смартфон%'
ORDER BY price DESC
LIMIT 5;
```

`LIKE` различает регистр. `ILIKE` — нет. Сравни два запроса: в каталоге есть «Наушники …» и «TWS-наушники …», и только `ILIKE` найдёт оба написания.

```sql
SELECT COUNT(*) AS cnt
FROM products
WHERE name LIKE '%наушники%';
```

```sql
SELECT COUNT(*) AS cnt
FROM products
WHERE name ILIKE '%наушники%';
```

`NOT LIKE` и `NOT ILIKE` отбирают строки, которые **не** подходят под шаблон.

### Если нужен сам символ % или _

Чтобы искать буквальный `%` или `_`, их экранируют обратной косой чертой: `LIKE '%\_%'` найдёт строки с подчёркиванием.

### Регулярные выражения

Для сложных шаблонов в PostgreSQL есть регулярные выражения: `~` (с учётом регистра) и `~*` (без). Например, товары, у которых название заканчивается на двузначное число:

```sql
SELECT name
FROM products
WHERE name ~ '[0-9]{2}$'
LIMIT 5;
```

В тикетах регулярки не обязательны, но в реальной работе — при чистке телефонов, артикулов и почт — они очень выручают.

> **Ловушка.** Шаблон `'%Nova%'` найдёт и «Nova», и «Novatek», и «Supernova». Если нужен точный бренд, сравнивай колонку `brand = 'Nova'`, а не название по шаблону.

## NULL: значение неизвестно

`NULL` — это не ноль и не пустая строка. Это отметка «значение отсутствует или неизвестно». У клиента может не быть телефона, у заказа — адреса, у отзыва — текста, у доставки — даты вручения (заказ ещё в пути).

### Трёхзначная логика

Любое сравнение с NULL даёт не «истину» и не «ложь», а третий результат — **unknown** (тоже NULL). Неизвестно, равен ли неизвестный телефон чему-то, — значит, и ответ неизвестен.

| Выражение | Результат |
| --- | --- |
| `NULL = 5` | NULL |
| `NULL = NULL` | NULL |
| `NULL <> 5` | NULL |
| `NULL > 0` | NULL |
| `TRUE AND NULL` | NULL |
| `FALSE AND NULL` | FALSE |
| `TRUE OR NULL` | TRUE |
| `FALSE OR NULL` | NULL |
| `NOT NULL` | NULL |

`WHERE` пропускает только строки с результатом TRUE. Строки с FALSE и с NULL отбрасываются одинаково.

### IS NULL и IS NOT NULL

Поэтому `phone = NULL` не найдёт ни одной строки — даже у клиентов без телефона результат сравнения NULL, а не TRUE.

```sql
SELECT COUNT(*) AS cnt
FROM customers
WHERE phone = NULL;
```

Для проверки на NULL есть специальные операторы:

```sql
SELECT COUNT(*) AS without_phone
FROM customers
WHERE phone IS NULL;
```

```sql
SELECT COUNT(*) AS with_phone
FROM customers
WHERE phone IS NOT NULL;
```

### NULL прячется в отрицаниях

Самая коварная ситуация — условие «не равно». Допустим, нужны отзывы, текст которых не «Отлично». Запрос `WHERE text <> 'Отлично'` **не вернёт отзывы без текста**: для них `NULL <> 'Отлично'` — это NULL, и строка отбрасывается. Если отзывы без текста тоже нужны, это надо сказать явно:

```sql-static
WHERE text <> 'Отлично' OR text IS NULL
```

Или короче — оператором, который считает NULL обычным значением:

```sql-static
WHERE text IS DISTINCT FROM 'Отлично'
```

`IS DISTINCT FROM` — это «не равно», для которого `NULL` и `NULL` равны, а `NULL` и `'Отлично'` — различны. Его пара — `IS NOT DISTINCT FROM`.

> **Важно.** Каждый раз, когда пишешь условие по колонке, которая может быть NULL, спроси себя: «Что должно случиться со строками, где тут NULL?» Половина ошибок в аналитических отчётах — от забытого ответа на этот вопрос.

### Как узнать, где бывают NULL

Ограничение `NOT NULL` в схеме гарантирует, что пропусков нет. В ShopData пропуски бывают в `customers.phone`, `customers.birth_date`, `orders.delivery_address`, `reviews.text`, `deliveries.delivered_at`, `categories.parent_id` и `employees.manager_id`. Быстрая проверка любой колонки:

```sql
SELECT COUNT(*) AS total,
       COUNT(birth_date) AS with_birth_date
FROM customers;
```

`COUNT(колонка)` считает только не-NULL значения — подробнее об этом на уровне 3.

## Фильтры по выражениям

В `WHERE` можно сравнивать не только колонки, но и выражения:

```sql
SELECT name, price, cost
FROM products
WHERE price - cost > 50000
ORDER BY price - cost DESC;
```

```sql
SELECT first_name, last_name, email
FROM customers
WHERE lower(email) LIKE '%@yandex.ru'
LIMIT 5;
```

Функции для текста и дат подробно разберём на уровне 2.

### Почему в WHERE нельзя использовать псевдоним

```sql-error
SELECT name, price - cost AS margin
FROM products
WHERE margin > 50000;
```

`WHERE` выполняется раньше `SELECT`, и псевдонима `margin` в этот момент ещё нет. Выражение придётся повторить или вынести в подзапрос (уровень 5) либо CTE (уровень 6).

## Типичные ошибки

### Двойные кавычки вокруг текста

```sql-error
SELECT first_name
FROM customers
WHERE city = "Казань";
```

Для PostgreSQL `"Казань"` — имя колонки, а такой колонки нет. Текст пишется в одинарных кавычках.

### OR без скобок

`WHERE brand = 'Nova' OR brand = 'Volt' AND price < 2000` отберёт все товары Nova и только дешёвые Volt. Нужны скобки: `(brand = 'Nova' OR brand = 'Volt') AND price < 2000` или `brand IN ('Nova', 'Volt') AND price < 2000`.

### Конец периода через BETWEEN

`BETWEEN '2026-06-01' AND '2026-06-30'` для колонки с временем теряет последний день. Используй `>= '2026-06-01' AND < '2026-07-01'`.

### Сравнение с NULL через =

`WHERE phone = NULL` и `WHERE phone <> NULL` всегда пусты. Только `IS NULL` / `IS NOT NULL`.

### Отрицание теряет NULL

`WHERE courier <> 'СДЭК'` не вернёт строки, где курьер неизвестен. Если они нужны, добавь `OR courier IS NULL` или используй `IS DISTINCT FROM`.

### Шаблон без процентов

`LIKE 'Nova'` — это то же, что `= 'Nova'`. Чтобы искать подстроку, нужны `%` по краям: `LIKE '%Nova%'`.

## Шпаргалка

| Задача | Условие |
| --- | --- |
| Равно / не равно | `city = 'Казань'`, `status <> 'cancelled'` |
| Одно из значений | `status IN ('new', 'paid')` |
| Ни одно из значений | `department NOT IN ('Продажи', 'Поддержка')` |
| Числовой диапазон | `price BETWEEN 1000 AND 2000` |
| Период по времени | `created_at >= '2026-06-01' AND created_at < '2026-07-01'` |
| Начинается с | `name LIKE 'Смартфон%'` |
| Содержит, без учёта регистра | `name ILIKE '%наушники%'` |
| Значение отсутствует | `phone IS NULL` |
| Значение есть | `phone IS NOT NULL` |
| «Не равно», NULL считается значением | `text IS DISTINCT FROM 'Отлично'` |
| Логическая колонка | `WHERE is_active`, `WHERE NOT is_active` |
| Сложное условие | `(a OR b) AND c` — со скобками |

## Проверь себя

?? Что вернёт `SELECT COUNT(*) FROM customers WHERE phone <> '+7 900 000-00-00'` — всех клиентов?
:: Нет. Клиенты без телефона не попадут: для них сравнение даёт NULL. Посчитаются только клиенты, у которых телефон есть и он другой.

?? Чем `price BETWEEN 1000 AND 2000` отличается от `price > 1000 AND price < 2000`?
:: BETWEEN включает границы: товары ровно за 1000 и 2000 попадут в результат. Второе условие их исключает.

?? Как найти всех клиентов с почтой на gmail.com, если домен иногда записан заглавными буквами?
:: `WHERE email ILIKE '%@gmail.com'` или `WHERE lower(email) LIKE '%@gmail.com'`.

?? Что вернёт `WHERE NOT (city = 'Москва')` для клиента, у которого город NULL?
:: Ничего: `city = 'Москва'` даёт NULL, `NOT NULL` — тоже NULL, строка отбрасывается. В ShopData у клиентов город всегда заполнен, но в чужих данных об этом стоит помнить.

?? Почему `WHERE created_at::date = '2026-06-15'` работает правильно, а `WHERE created_at = '2026-06-15'` — нет?
:: Второе сравнивает время заказа ровно с полуночью 15 июня и найдёт только заказы, оформленные в 00:00:00. Первое отрезает время и сравнивает даты. Ещё лучше для больших таблиц — полуоткрытый интервал `>= '2026-06-15' AND < '2026-06-16'`: на уровне 11 станет понятно почему.

?? `a OR b AND c` — в каком порядке это вычисляется?
:: Как `a OR (b AND c)`: AND связывает сильнее.
